# JavaScript 执行上下文

## 一句话总结

执行上下文是代码执行时的环境，它包含了变量、函数、`this` 等信息，决定了代码能访问哪些变量。

---

## 核心概念

### 1. 什么是执行上下文？

JavaScript 引擎在执行代码时，会创建一个"环境"来管理代码的执行，这个环境就是**执行上下文**。

```javascript
// 全局执行上下文
let x = 10;

function foo() {
    // 函数执行上下文
    let y = 20;
    console.log(x + y);
}

foo();  // 30
```

### 2. 三种执行上下文类型

| 类型 | 说明 | 示例 |
|---|---|---|
| 全局执行上下文 | 代码最外层的环境 | 浏览器中是 `window`，Node.js 中是 `global` |
| 函数执行上下文 | 函数被调用时创建 | 每次调用函数都会创建新的执行上下文 |
| Eval 执行上下文 | `eval()` 函数执行时创建 | 不推荐使用 |

### 3. 执行上下文的生命周期

```
┌─────────────────────────────────────┐
│           执行上下文生命周期           │
├─────────────────────────────────────┤
│ 1. 创建阶段（Creation Phase）         │
│    - 创建变量对象（VO）               │
│    - 建立作用域链（Scope Chain）       │
│    - 确定 this 指向                  │
│                                     │
│ 2. 执行阶段（Execution Phase）        │
│    - 执行代码                        │
│    - 变量赋值                        │
│    - 函数引用                        │
└─────────────────────────────────────┘
```

## 执行上下文的详细内容

### 1. 变量对象（Variable Object）

**创建阶段：**

```javascript
// 代码
let x = 10;
function foo() { return 1; }
var y = 20;
```

**变量对象的创建过程：**

```
1. 扫描代码，找到所有声明
2. 将 var 声明的变量放入 VO（值为 undefined）
3. 将 function 声明的函数放入 VO（值为函数本身）
4. let/const 声明的变量暂时不放入（TDZ）
```

```
变量对象（VO）：
┌─────────────────────────────┐
│ arguments: undefined（非函数）│
│ foo: function foo() {...}   │
│ y: undefined                │
│ x: undefined（let 暂时存 TDZ）│
└─────────────────────────────┘
```

**执行阶段：**

```
变量对象（VO）：
┌─────────────────────────────┐
│ foo: function foo() {...}   │
│ y: 20                       │
│ x: 10                       │
└─────────────────────────────┘
```

### 2. 作用域链（Scope Chain）

**作用域链 = 当前变量对象 + 所有父级变量对象**

```javascript
let globalVar = "global";

function outer() {
    let outerVar = "outer";
    
    function inner() {
        let innerVar = "inner";
        console.log(globalVar);  // 能访问
        console.log(outerVar);   // 能访问
        console.log(innerVar);   // 能访问
    }
    
    inner();
}

outer();
```

```
inner 的作用域链：
┌─────────────────────────────┐
│ inner 的变量对象             │
│   innerVar: "inner"         │
├─────────────────────────────┤
│ outer 的变量对象             │
│   outerVar: "outer"         │
├─────────────────────────────┤
│ 全局变量对象                  │
│   globalVar: "global"       │
└─────────────────────────────┘
```

### 3. this 绑定

**在创建阶段确定 this 的指向：**

```javascript
// 全局执行上下文
console.log(this);  // window

// 函数执行上下文
function foo() {
    console.log(this);
}

let obj = { name: "Peng" };
foo.call(obj);  // obj
```

## 执行上下文栈（Execution Context Stack）

**JavaScript 引擎用栈来管理执行上下文：**

```javascript
let x = 10;

function foo() {
    let y = 20;
    bar();
}

function bar() {
    let z = 30;
    console.log(x + y + z);
}

foo();
```

**执行过程：**

```
1. 创建全局执行上下文，压入栈底
┌─────────────────┐
│ 全局执行上下文     │
└─────────────────┘

2. 调用 foo()，创建 foo 的执行上下文，压入栈
┌─────────────────┐
│ foo 执行上下文    │
├─────────────────┤
│ 全局执行上下文     │
└─────────────────┘

3. 调用 bar()，创建 bar 的执行上下文，压入栈
┌─────────────────┐
│ bar 执行上下文    │ ← 栈顶（当前执行）
├─────────────────┤
│ foo 执行上下文    │
├─────────────────┤
│ 全局执行上下文     │
└─────────────────┘

4. bar() 执行完毕，弹出栈
┌─────────────────┐
│ foo 执行上下文    │ ← 继续执行
├─────────────────┤
│ 全局执行上下文     │
└─────────────────┘

5. foo() 执行完毕，弹出栈
┌─────────────────┐
│ 全局执行上下文     │ ← 继续执行
└─────────────────┘
```

## 变量提升（Hoisting）

**变量提升是执行上下文创建阶段的产物：**

```javascript
console.log(x);  // undefined（不是报错！）
var x = 10;

console.log(y);  // ReferenceError: Cannot access 'y' before initialization
let y = 20;
```

**为什么 var 是 undefined，let 是 ReferenceError？**

```
var 的处理：
创建阶段 → 放入 VO，值为 undefined
执行阶段 → 赋值为 10

let 的处理：
创建阶段 → 放入 VO，但处于暂时性死区（TDZ）
执行阶段 → 赋值为 20
```

### 暂时性死区（Temporal Dead Zone）

```javascript
let x = 10;

function foo() {
    console.log(x);  // ReferenceError: Cannot access 'x' before initialization
    let x = 20;
}

foo();
```

**原因：** 函数内部有自己的 `x`，在 `let x = 20` 之前，`x` 处于 TDZ，不能访问。

## 执行上下文与闭包的关系

```javascript
function outer() {
    let count = 0;
    
    function inner() {
        count++;
        console.log(count);
    }
    
    return inner;
}

let counter = outer();
counter();  // 1
counter();  // 2
```

**闭包的本质：** 内部函数引用了外部函数的变量对象，即使外部函数执行上下文已销毁，变量对象仍然被内部函数引用。

```
outer() 执行上下文销毁后：
┌─────────────────────────────┐
│ outer 的变量对象（仍然存在）   │
│   count: 0                   │
│   inner: function            │
├─────────────────────────────┤
│ inner 的执行上下文             │
│   引用 outer 的变量对象        │
└─────────────────────────────┘
```

## 动手验证

```javascript
// 测试 1：变量提升
console.log(a);  // undefined
var a = 1;

// 测试 2：函数声明提升
console.log(b());  // "hello"（函数声明会提升）
function b() {
    return "hello";
}

// 测试 3：函数表达式不提升
console.log(c);  // undefined
var c = function() {
    return "world";
};

// 测试 4：let/const 的 TDZ
{
    console.log(d);  // ReferenceError
    let d = 1;
}

// 测试 5：作用域链
function outer() {
    let x = 10;
    function inner() {
        console.log(x);  // 10（访问外层作用域）
    }
    inner();
}
outer();

// 测试 6：执行上下文栈
function first() {
    console.log("first start");
    second();
    console.log("first end");
}

function second() {
    console.log("second");
}

console.log("global start");
first();
console.log("global end");

// 输出：
// global start
// first start
// second
// first end
// global end
```

## 容易混淆的地方

1. **变量提升是创建阶段的产物** — 不是代码真的"移到"了前面
2. **let/const 有 TDZ** — 不是"不提升"，而是"提升了但不能用"
3. **函数声明会提升整个函数** — 函数表达式只提升变量声明
4. **执行上下文栈是 LIFO** — 后进先出，和调用栈一样

## 实际开发中的应用

```javascript
// Vue 2 的 data 函数每次调用都创建新的执行上下文
export default {
    data() {
        return {
            count: 0  // 每个组件实例都有独立的 count
        };
    }
};

// 理解变量提升避免 bug
function foo() {
    console.log(x);  // undefined，不是 ReferenceError
    var x = 10;
}

// 理解 TDZ 避免 bug
function bar() {
    // 这里不能使用 x
    let x = 10;
}
```
