# JavaScript 原型系统（Prototype System）完整笔记

---

# 1. 原型系统是什么？

JavaScript 的原型系统，本质是：

> **JS 实现“对象复用 + 继承”的机制**

因为 JS 没有传统类（早期），所以用：

```text
对象 → 原型 → 原型的原型 → ... → null
```

构成链式结构：

> **原型链（Prototype Chain）**

---

# 2. 三个核心概念（必须先搞清）

---

## 2.1 prototype（函数的属性）

只有 **函数** 才有 `prototype`

```js
function Person() {}
console.log(Person.prototype)
```

👉 它的作用：

> 给“通过 new 创建的对象”使用

---

## 2.2 **proto**（对象的隐式原型）

所有对象都有：

```js
const obj = {}
console.log(obj.__proto__)
```

👉 它指向：

> 创建这个对象的构造函数的 prototype

---

## 2.3 constructor（构造函数引用）

```js
function Person() {}

const p = new Person()

p.constructor === Person // true
```

---

# 3. 三者关系图（核心）

```text
Person（构造函数）
   |
   | prototype
   ↓
Person.prototype  <----------------
   |                                |
   | __proto__                     constructor
   ↓                                |
Object.prototype                   Person
   |
   ↓
null
```

---

# 4. new 做了什么？（非常重要）

```js
const p = new Person()
```

等价于：

```js
const p = {}

// 1. 绑定原型
p.__proto__ = Person.prototype

// 2. 执行构造函数
Person.call(p)

// 3. 返回对象
return p
```

---

## 一句话总结：

> new = 创建对象 + 绑定原型 + 执行构造函数

---

# 5. 原型链是什么？

访问属性时：

```js
p.name
```

查找顺序：

```text
1. p 自身
2. p.__proto__
3. p.__proto__.__proto__
4. ...
5. null → undefined
```

---

# 6. 示例理解原型链

```js
function Person() {}
Person.prototype.say = function () {
  console.log('hello')
}

const p = new Person()

p.say()
```

执行过程：

```text
p 自身没有 say
→ 去 Person.prototype 找
→ 找到执行
```

---

# 7. instanceof 原理（必须掌握）

```js
p instanceof Person
```

本质：

> Person.prototype 是否在 p 的原型链上

等价：

```js
p.__proto__ === Person.prototype
或
p.__proto__.__proto__ === Person.prototype
```

---

# 8. Object 是原型链顶层

```text
Object.prototype.__proto__ === null
```

说明：

> 原型链最终终点是 null

---

# 9. 函数也是对象（重点）

```js
function fn() {}
```

它同时具备：

```text
fn.__proto__  → Function.prototype
fn.prototype  → 给 new 用
```

👉 所以函数是“双重身份”

---

# 10. Function / Object 关系（容易混乱点）

```js
Function.__proto__ === Function.prototype // true
Object.__proto__ === Function.prototype
```

说明：

> Function 是所有函数的构造器

---

# 11. 原型继承（核心应用）

---

## 11.1 经典继承（构造函数）

```js
function Parent() {
  this.name = 'parent'
}

function Child() {}

Child.prototype = new Parent()
```

---

## 问题：

```text
Child.prototype.constructor 丢失
```

需要修复：

```js
Child.prototype.constructor = Child
```

---

## 11.2 ES6 class 继承（语法糖）

```js
class Parent {}

class Child extends Parent {}
```

本质：

```text
Child.prototype.__proto__ = Parent.prototype
```

---

# 12. 原型污染（面试点）

```js
Object.prototype.a = 1

const obj = {}

console.log(obj.a) // 1 ❌
```

👉 所有对象都会受到影响

---

# 13. 判断属性来源

---

## hasOwnProperty

```js
obj.hasOwnProperty('key')
```

判断：

> 是否是对象自身属性

---

## in

```js
'key' in obj
```

判断：

> 原型链 + 自身

---

# 14. Object.create（重要）

```js
const obj = Object.create(null)
```

特点：

```text
没有原型链
```

👉 常用于：

* Map 替代方案
* 安全对象（无污染）

---

# 15. 原型系统的本质总结

一句话讲透：

> JavaScript 原型系统 = 对象之间的“委托关系链”

不是复制，而是：

```text
访问不到 → 去原型找
```

---

# 16. 常见面试陷阱

---

## ❌ 1. p.prototype（错误）

```js
p.prototype // undefined
```

👉 prototype 只有函数有

---

## ❌ 2. **proto** 等于 prototype（错误）

```js
p.__proto__ === Person.prototype // true
```

但：

```js
Person.__proto__ !== Person.prototype
```

---

## ❌ 3. 改 prototype 会影响所有实例

```js
Person.prototype.say = fn
```

所有 new 出来的对象都会变

---

# 17. 手写原型链核心模型

```js
function myNew(fn, ...args) {
  const obj = {}

  obj.__proto__ = fn.prototype

  const result = fn.apply(obj, args)

  return result instanceof Object ? result : obj
}
```

---

# 18. 原型系统核心图（最终总结）

```text
对象
  ↓
__proto__
  ↓
prototype
  ↓
Object.prototype
  ↓
null
```

---

# 19. 一句话终极理解

> JavaScript 原型系统的本质，是“对象属性查找的委托链机制”，不是传统意义的类继承。
