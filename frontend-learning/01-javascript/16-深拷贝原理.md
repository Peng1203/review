# 深拷贝原理

## 前置知识 & 知识网络

- **依赖**：引用类型与栈/堆、垃圾回收、WeakMap/WeakRef、`Reflect.ownKeys`
- **影响**：表单数据隔离、状态快照、Vue 不可变更新、Vuex/Pinia 新对象触发更新

---

## 一句话总结

浅拷贝只复制"第一层引用"（嵌套对象仍共享），深拷贝要**递归复制整棵对象图**，让新对象与原对象彻底无关；实现难点在于处理**循环引用**（用 WeakMap 记"已拷贝的原对象"）、**特殊类型**（Date/Map/Set/RegExp 等）以及**不能拷贝的内容**（函数、Symbol）。

---

## 背景：为什么需要深拷贝？

### 1. 从"引用共享"说起

JS 里对象是引用类型，赋值只复制引用：

```javascript
const original = { user: { name: 'Peng' } }
const copy = original          // 只是多了一个指向同一对象的"指针"

copy.user.name = '改名了'
console.log(original.user.name) // '改名了' —— 两个"副本"其实是一个对象
```

业务里经常需要**独立的副本**：表单编辑不想污染原数据、状态快照（撤销/历史）、跨组件传值避免互相影响。这时就需要拷贝。

### 2. 浅拷贝只解决"第一层"

```javascript
const shallow = { ...original }        // 展开运算符
const shallow2 = Object.assign({}, original)

shallow.user.name = '还是会被改'       // ❌ 嵌套的 user 仍是同一个引用
shallow.user = { name: '新对象' }      // ✅ 只有整体替换第一层属性才互不影响
```

浅拷贝把"第一层的值/引用"复制了一份：第一层如果是基本类型就真正独立，如果是对象，复制出来的还是指向同一对象的引用。**嵌套越深，浅拷贝越不够用。**

## 第一节：JSON 序列化方案（最常用，但坑最多）

```javascript
const deepCopy = JSON.parse(JSON.stringify(original))
```

思路：先"序列化成字符串"，再"解析回对象"——中间的字符串斩断了所有引用关系。但它有**四大坑**：

| 问题 | 表现 |
|---|---|
| 函数 / undefined / Symbol | 直接被**丢弃**（数组里的会变 null） |
| Date | 变成字符串，不再是 Date 对象 |
| RegExp / Map / Set | 变成 `{}` 空对象 |
| 循环引用 | 直接抛错 `TypeError: Converting circular structure to JSON` |

```javascript
const obj = {
  fn: () => 1,
  date: new Date(),
  map: new Map([['k', 'v']]),
  undef: undefined,
}
JSON.parse(JSON.stringify(obj))
// { date: "2026-...", map: {} } —— fn/undef 没了，date 变字符串，map 变 {}
```

**结论**：只有"纯 JSON 数据"（字面量对象/数组 + 基本类型）用它才安全。

## 第二节：手写递归深拷贝（理解原理的核心）

深拷贝本质是**遍历 + 逐层复制**：

```javascript
function deepClone(target, map = new WeakMap()) {
  // 1. 基本类型 / 函数：直接返回
  if (target === null || typeof target !== 'object') return target

  // 2. 循环引用处理：已经拷过就直接返回它的拷贝
  if (map.has(target)) return map.get(target)

  // 3. 特殊类型处理（Date / RegExp / Map / Set ...）
  if (target instanceof Date) return new Date(target)
  if (target instanceof RegExp) return new RegExp(target.source, target.flags)
  if (target instanceof Map) {
    const copy = new Map()
    map.set(target, copy)              // 先登记再递归，防止循环引用
    target.forEach((val, key) => copy.set(key, deepClone(val, map)))
    return copy
  }
  if (target instanceof Set) {
    const copy = new Set()
    map.set(target, copy)
    target.forEach(val => copy.add(deepClone(val, map)))
    return copy
  }

  // 4. 数组 / 普通对象：建新容器，递归复制每个属性
  const clone = Array.isArray(target) ? [] : {}
  map.set(target, clone)               // 先登记（关键！循环引用靠它）
  for (const key of Reflect.ownKeys(target)) {
    clone[key] = deepClone(target[key], map)
  }
  return clone
}
```

**三个关键设计**：

1. **基本类型直接返回**（深拷贝的终点）
2. **先登记再递归**（`map.set` 放在递归之前）——处理循环引用：当递归遇到"回到自己"时，能从 map 里拿到已经建好的拷贝
3. **用 WeakMap 做登记表**——拷完原对象就没人引用它了，WeakMap 弱引用让登记表不阻止 GC 回收（呼应垃圾回收章节）

循环引用示例：

```javascript
const a = {}
a.self = a                    // 自己引用自己
const copy = deepClone(a)     // 不抛错
copy.self === copy            // true，且 copy.self 不会无限递归
```

## 第三节：structuredClone（浏览器/Node 原生，推荐）

现代环境提供的**标准深拷贝 API**，官方实现，能处理循环引用 + Date/Map/Set/RegExp/ArrayBuffer 等几乎所有内置类型：

```javascript
const copy = structuredClone(original)
```

**唯一限制**：不能拷贝**函数**和 **Symbol**（遇到会抛 `DataCloneError`）；原型链也不复制（拷成普通对象）。但这恰好是绝大多数业务数据不涉及的部分。

> 对比记忆：JSON 方案 < 手写递归（可控） < structuredClone（内置权威）。浏览器兼容性：Chrome 98+ / Node 17+ 已广泛可用。

## 结合实际开发

**什么时候必须深拷贝？**

- 表单编辑 vs 原数据隔离
- 撤销/重做、历史快照
- 状态管理里不可变更新（Vue/Vuex 需要新对象触发更新）
- 跨组件传 props 防止子组件改到父组件数据

**什么时候别深拷贝（性能）？**

- 大对象频繁拷贝很贵（递归 + 大量新对象）
- 只是读不写 → 直接传引用即可
- Vue 中优先用**不可变更新（返回新引用）而非整体深拷贝**——深拷贝会破坏对象身份，让响应式/缓存全部失效

> Vue 里常配合的工具：lodash `_.cloneDeep`。它比我们手写的多了对 `Buffer`、`TypedArray`、原型保持等的处理，本质思路完全一样（递归 + WeakMap 循环引用表）。

## 框架设计思想

1. **为什么拷贝不能"图省事用 JSON"？** 因为 JSON 是**数据交换格式**，不是对象模型——它天然无法表达函数、undefined、循环。用它拷贝对象是"杀鸡用错刀"。
2. **为什么 structuredClone 禁止拷贝函数？** 函数本质是"代码 + 闭包环境"，复制语义不明确（是复制源码？还是复制闭包？），规范选择**干脆报错**——又是一个"宁可 fail fast，不给模糊语义"的例子。
3. **为什么循环引用用 WeakMap 而不用 Map？** 拷贝过程是临时的，用强引用 Map 会让登记表在拷贝结束后仍持有所有原对象（泄漏），WeakMap 则让登记表随拷贝结束自动可回收。**这是前面 GC + WeakRef 两章知识点的实际应用。**

---

## 总结

**核心知识**：浅拷贝（第一层）vs 深拷贝（递归整图）；JSON 方案的四大坑；手写递归三要点（基本类型出口 / 先登记防循环 / WeakMap 登记表）；structuredClone 作为标准答案。

**容易混淆**：

- 展开运算符 `{...}` 是**浅拷贝**，不是深拷贝
- JSON 拷贝会**静默丢数据**（函数/undefined 消失），比报错更危险
- 循环引用不是"必须避免"，而是"拷贝时要处理"

**实际应用**：普通 JSON 数据用 structuredClone；需要控制类型处理时用手写/loadsh cloneDeep；纯数据用 JSON 也行但要知道边界。
