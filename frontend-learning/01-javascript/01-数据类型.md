# JavaScript 数据类型

## 一句话总结

JS 有 8 种数据类型，分为原始类型（存储值）和引用类型（存储引用），理解它们的区别是理解 JS 内存管理和行为的基础。

---

## 核心概念

### 1. 8 种数据类型

| 类型        | typeof 返回值    | 示例                                     |
| --------- | ------------- | -------------------------------------- |
| Number    | `"number"`    | `42`, `3.14`, `NaN`, `Infinity`        |
| String    | `"string"`    | `"hello"`, `'world'`, `` `template` `` |
| Boolean   | `"boolean"`   | `true`, `false`                        |
| Undefined | `"undefined"` | `undefined`                            |
| Null      | `"object"` ⚠️ | `null`                                 |
| Symbol    | `"symbol"`    | `Symbol('id')`                         |
| BigInt    | `"bigint"`    | `9007199254740991n`                    |
| Object    | `"object"`    | `{}`, `[]`, `function(){}`             |

### 2. 原始类型 vs 引用类型

```
原始类型（栈内存）          引用类型（堆内存）
┌──────────┐              ┌──────────┐
│ x = 1    │              │ obj      │
│ y = 1    │              │ ↓ 指针    │
│ a = "hi" │              │ → {name: "Peng"} │
└──────────┘              └──────────┘
  值直接存储                存储的是地址
```

**关键区别：**

- 原始类型：赋值时**复制值**，修改互不影响
- 引用类型：赋值时**复制引用**，修改会互相影响

### 3. typeof 的坑

```javascript
typeof 123          // "number"
typeof "hello"      // "string"
typeof true         // "boolean"
typeof undefined    // "undefined"
typeof null         // "object" ← 历史遗留 bug
typeof {}           // "object"
typeof []           // "object"
typeof function(){} // "function"
```

**为什么 typeof null 是 "object"？**

JS 最初用 32 位存储类型信息，前 3 位是类型标志：

- `000` = 对象
- `null` 全是 0，所以被错误识别为对象

这是 JS 最著名的 bug，但永远不会修复（会破坏现有代码）。

### 4. 原始类型的不可变性

```javascript
let str = "hello";
str.toUpperCase();  // 不会修改原字符串
console.log(str);   // "hello" ← 原值不变

// 字符串方法返回新字符串，不是修改原字符串
let upper = str.toUpperCase();  // "HELLO"
```

### 5. 隐式类型转换（面试高频）

```javascript
// 数字 + 字符串 → 字符串
1 + "2"     // "12"

// 数字 - 字符串 → 数字
"5" - 2     // 3

// 比较时的类型转换
"5" == 5    // true（宽松相等，会转换类型）
"5" === 5   // false（严格相等，不转换类型）
```

**规则：**

- `==` 会做类型转换，结果不可预测
- `===` 不做类型转换，推荐始终使用

### 6. NaN 的特殊性

```javascript
NaN === NaN  // false ← NaN 不等于任何值，包括自己

// 正确判断 NaN
Number.isNaN(NaN)  // true
```

### 7. 数据类型判断的最佳实践

```javascript
// 判断原始类型
typeof value === "string"
typeof value === "number"
typeof value === "boolean"
typeof value === "undefined"

// 判断 null
value === null

// 判断对象（包括数组、函数等）
typeof value === "object" && value !== null

// 判断数组
Array.isArray(value)

// 判断具体对象类型（需要 instanceof）
value instanceof Date
```

## 动手验证

```javascript
// 测试 1：原始类型赋值
let a = 1;
let b = a;
b = 2;
console.log(a); // 1 ← a 不受影响

// 测试 2：引用类型赋值
let obj1 = { name: "Peng" };
let obj2 = obj1;
obj2.name = "changed";
console.log(obj1.name); // "changed" ← obj1 也变了

// 测试 3：typeof 的坑
console.log(typeof null);        // "object"
console.log(typeof undefined);   // "undefined"
console.log(typeof NaN);         // "number"

// 测试 4：隐式类型转换
console.log(1 + "2");    // "12"
console.log("5" - 2);    // 3
console.log(true + 1);   // 2
console.log(false + "");  // "0" 不是 "false"
```

---

## 容易混淆的地方

1. **typeof null === "object"** — 这是 bug，记住就好
2. **NaN !== NaN** — NaN 不等于任何值
3. **引用类型赋值是"共享引用"** — 不是复制对象
4. **字符串是不可变的** — 所有方法返回新字符串

---

## 实际开发中的应用

- **判断数据类型**：写工具函数、表单验证、API 响应处理
- **避免引用类型陷阱**：深拷贝、解构赋值、展开运算符
- **理解隐式转换**：避免 `==`，用 `===`
- **内存管理**：理解引用类型会占用更多内存
