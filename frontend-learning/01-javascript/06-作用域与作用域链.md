# JavaScript 作用域与作用域链

## 一句话总结

作用域决定了代码中变量能被访问的范围，作用域链是 JavaScript 引擎按层级查找变量的路径。

---

## 背景

### 1. 为什么需要作用域？

假设没有作用域，代码中的变量会全部混在一起：

```javascript
// 假想：没有作用域的世界
let count = 0

function foo() {
  count = 10 // 意外修改了外部变量！
}

function bar() {
  count = 20 // 又被修改了！
}
```

这会导致变量被随意修改，代码变得不可预测。

**作用域的出现，就是为了避免变量冲突和意外修改。**

### 2. 作用域解决什么问题？

| 问题           | 解决方案                                   |
| -------------- | ------------------------------------------ |
| 变量命名冲突   | 每个作用域有自己的变量空间                 |
| 变量被意外修改 | 内部作用域无法访问外部变量（除非故意暴露） |
| 代码组织性差   | 按功能模块划分作用域                       |

## 核心概念

### 1. 什么是作用域？

作用域是指代码中变量可以被访问的区域。

```javascript
let globalVar = '全局变量'

function outer() {
  let outerVar = '外层变量'

  function inner() {
    let innerVar = '内层变量'
    console.log(innerVar) // ✓ 可以访问
    console.log(outerVar) // ✓ 可以访问
    console.log(globalVar) // ✓ 可以访问
  }

  inner()
  console.log(innerVar) // ✗ 报错！innerVar 是 inner 的局部变量
}
```

### 2. 作用域的层级

```
┌─────────────────────────────────────┐
│          全局作用域（Global）          │
│  ┌─────────────────────────────────┐ │
│  │      函数作用域（Function）      │ │
│  │  ┌───────────────────────────┐  │ │
│  │  │   块级作用域（Block）      │  │ │
│  │  │   let / const 变量        │  │ │
│  │  └───────────────────────────┘  │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
```

## 底层原理

### 1. 作用域链的形成

当 JavaScript 引擎查找变量时，会沿着作用域链从内到外查找：

```javascript
let globalVar = '全局'

function outer() {
  let outerVar = '外层'

  function inner() {
    let innerVar = '内层'
    console.log(innerVar) // 1. 先在当前作用域找
    console.log(outerVar) // 2. 没找到，沿着作用域链向外找
    console.log(globalVar) // 3. 继续向外找，直到全局作用域
  }

  return inner
}

let fn = outer()
fn()
```

### 2. 作用域链的内部结构

```
inner 函数的作用域链：
┌──────────────────────────────────────────────┐
│  Scope Chain: [innerContext, outerContext, globalContext] │
├──────────────────────────────────────────────┤
│                                              │
│  innerContext                                │
│  ┌──────────────────────────────────────┐   │
│  │  innerVar = '内层'                    │   │
│  │  [[Scope]] → outerContext             │   │
│  └──────────────────────────────────────┘   │
│                    ↑                          │
│                    │ [[Scope]] 引用          │
│                    ↓                          │
│  outerContext                               │
│  ┌──────────────────────────────────────┐   │
│  │  outerVar = '外层'                    │   │
│  │  [[Scope]] → globalContext            │   │
│  └──────────────────────────────────────┘   │
│                    ↑                          │
│                    │ [[Scope]] 引用          │
│                    ↓                          │
│  globalContext                              │
│  ┌──────────────────────────────────────┐   │
│  │  globalVar = '全局'                   │   │
│  │  fn = outer 函数引用                   │   │
│  └──────────────────────────────────────┘   │
│                                              │
└──────────────────────────────────────────────┘
```

### 3. [[Scope]] 属性

每个函数创建时，都会记住创建时的作用域链，这个内部属性叫 `[[Scope]]`：

```javascript
function outer() {
  let x = 10
  function inner() {
    console.log(x)
  }
  return inner
}

// inner 函数被创建时，它的 [[Scope]] 包含了 outer 的作用域
// 即使 outer 执行完毕，只要 inner 还在被引用，outer 的作用域就不会被销毁
```

**关键点**：

- `[[Scope]]` 在函数**创建时**确定，不是调用时
- 这就是闭包能够访问外层变量的根本原因

## 流程图

### 变量查找流程

```
查找变量 x
      │
      ▼
┌─────────────┐
│ 当前作用域   │ ← 从这里开始
└─────────────┘
      │
      ├── 找到了？ ──→ 使用这个变量
      │
      └── 没找到？
              │
              ▼
      ┌─────────────┐
      │ 父级作用域   │
      └─────────────┘
              │
              ├── 找到了？ ──→ 使用这个变量
              │
              └── 没找到？
                      │
                      ▼
              ┌─────────────┐
              │ 祖父级作用域 │
              └─────────────┘
                      │
                      └── 继续向上...
                              │
                              ▼
                      ┌─────────────┐
                      │ 全局作用域   │
                      └─────────────┘
                              │
                              ├── 找到了？ ──→ 使用这个变量
                              │
                              └── 没找到？ ──→ ReferenceError
```

## 三种作用域类型

### 1. 全局作用域

```javascript
let globalVar = '我是全局变量'

function foo() {
  console.log(globalVar) // ✓ 可以访问
}
```

**特点**：

- 最外层声明的变量
- 任何地方都能访问
- 容易造成变量污染

### 2. 函数作用域

```javascript
function foo() {
  let localVar = '我是局部变量'
  console.log(localVar) // ✓ 可以访问
}

console.log(localVar) // ✗ ReferenceError
```

**特点**：

- `function` 内部声明的变量
- 只能在函数内部访问
- ES5 及之前只有函数作用域

### 3. 块级作用域

```javascript
{
  let blockVar = '我是块级变量'
  const blockConst = '我也是'
  console.log(blockVar) // ✓ 可以访问
}

console.log(blockVar) // ✗ ReferenceError

if (true) {
  let ifVar = 'if 块内的变量'
}
for (let i = 0; i < 3; i++) {
  // i 只在这个 for 循环内有效
}
```

**特点**：

- `let` 和 `const` 特有
- `{}` 大括号内有效
- 循环中的 `let` 每次迭代都会创建新变量

## 实际开发应用

### 1. 避免全局变量污染

**反例**：

```javascript
// utils.js
let count = 0
function increment() {
  count++
}

// app.js
let count = 100 // 冲突！覆盖了 utils.js 的 count
```

**正例**：

```javascript
// utils.js
const calculator = (function () {
  let count = 0 // 私有变量，不会污染全局

  function increment() {
    count++
  }
  function getCount() {
    return count
  }

  return { increment, getCount } // 只暴露需要的接口
})()
```

### 2. 模块化封装

```javascript
const Module = (function () {
  // 私有变量
  let privateData = []

  // 私有方法
  function privateMethod() {
    // ...
  }

  // 公开 API
  return {
    add: function (item) {
      privateData.push(item)
      privateMethod()
    },
    getAll: function () {
      return [...privateData] // 返回副本，防止外部修改
    },
  }
})()
```

### 3. 循环中的闭包问题

**问题代码**：

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i) // 输出 3, 3, 3 而不是 0, 1, 2
  }, 100)
}
```

**解决方案**：

```javascript
// 方案 1：使用 let（块级作用域）
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i) // 输出 0, 1, 2
  }, 100)
}

// 方案 2：使用 IIFE 创建新作用域
for (var i = 0; i < 3; i++) {
  ;(function (index) {
    setTimeout(function () {
      console.log(index) // 输出 0, 1, 2
    }, 100)
  })(i)
}
```

### 4. Vue 3 组合式 API 中的应用

```javascript
// Vue 3 组合式 API
import { ref, computed } from 'vue'

export default {
  setup() {
    // 每个 setup() 调用都是独立的作用域
    // 不会像 Vue 2 options API 那样担心数据属性名冲突

    const count = ref(0)
    const doubleCount = computed(() => count.value * 2)

    function increment() {
      count.value++
    }

    return { count, doubleCount, increment }
  },
}
```

## 框架设计思想

### 为什么 JavaScript 采用词法作用域？

JavaScript 使用的是**词法作用域（Lexical Scope）**，即作用域在代码编写时就决定了，而不是运行时。

```javascript
let x = 10

function foo() {
  console.log(x) // 这里的 x 指的是定义时所在的 x，而不是调用时的
}

function bar() {
  let x = 20
  foo() // 输出 10，而不是 20
}

bar()
```

**对比：动态作用域**（如 Bash 的 `eval`）会在运行时确定变量。

**词法作用域的优势**：

1. **可预测性**：代码行为在阅读时就能确定，不需要追踪运行时状态
2. **性能**：编译器可以在解析阶段就确定作用域链，优化查找
3. **易于分析**：IDE 可以准确告诉你变量来自哪里

### 作用域链的性能考虑

```javascript
// 避免在循环中重复访问作用域链
function badExample() {
  for (var i = 0; i < 1000; i++) {
    console.log(obj.method()) // 每次都要查找 obj
  }
}

function goodExample() {
  var method = obj.method // 缓存引用
  for (var i = 0; i < 1000; i++) {
    console.log(method()) // 直接使用缓存的引用
  }
}
```

## 总结

### 核心知识点

| 概念       | 说明                     |
| ---------- | ------------------------ |
| 作用域     | 变量能被访问的区域       |
| 作用域链   | 查找变量的路径，由内到外 |
| 词法作用域 | 作用域在代码编写时确定   |
| [[Scope]]  | 函数创建时记住的作用域链 |
| 全局作用域 | 最外层，所有地方都能访问 |
| 函数作用域 | function 内部，var 声明  |
| 块级作用域 | {} 内部，let/const 声明  |

### 闭包、作用域链、执行上下文的关系

```
执行上下文
    │
    ├── 包含：变量环境、词法环境、this 绑定
    │
    └── 包含：Scope（作用域链）
                  │
                  └── 指向：[[Scope]] 组成的链
                              │
                              └── 最终指向：全局作用域

闭包 = 函数 + 其 [[Scope]]（捕获外部作用域）
```

### 容易混淆的地方

| 混淆点               | 正确理解                                                     |
| -------------------- | ------------------------------------------------------------ |
| var 没有块级作用域   | `if (true) { var x = 1; }` 中 x 是函数作用域，不是块级作用域 |
| [[Scope]] 创建时确定 | 函数创建时就记住了作用域链，不是调用时                       |
| 作用域链和原型链     | 作用域链是找变量，原型链是找属性/方法                        |
| 词法作用域和 this    | 作用域链看代码位置，this 看调用方式                          |
